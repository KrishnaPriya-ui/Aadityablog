Eight Function Calls and a Folder Named public

Every web framework hides the same handful of operating-system calls behind a single line of code. This project doesn't. Written in C against the raw Windows Sockets API, it opens a TCP socket, reads an HTTP request by hand, and answers it by reading a file off disk — the same mechanics sitting underneath Node, Apache, and nginx, just not hidden this time.

What it actually does

Point a browser at http://localhost:8080/ and a few things happen in order: a TCP connection opens, the browser sends a plain-text request, the server reads it, maps the requested path onto a file inside a folder named public, works out what kind of file it is, and streams it back. If the file isn't there, it sends a 404 instead. That's the whole job.

  • Listens on TCP port 8080
  • Reads and parses a raw HTTP request by hand
  • Maps URL paths onto files inside ./public
  • Detects MIME type from the file extension
  • Streams files back in chunks, never all at once
  • Returns a 404 for anything missing
  • Blocks the simplest form of directory traversal
  • Handles one client at a time, start to finish

None of it needs a framework. It needs eight WinSock functions, a dozen C standard library calls, and some care with pointers. That's what the rest of this walks through, roughly in the order the code actually runs.

Waking up WinSock

Nothing else works until Windows' networking subsystem is loaded into the process. That's the only job of WSAStartup(), and it has to run before the first socket exists.

server.c
WSADATA wsa;

if (WSAStartup(MAKEWORD(2, 2), &wsa) != 0) {
    printf("Failed. Error Code : %d\n", WSAGetLastError());
    return 1;
}

MAKEWORD(2, 2) requests WinSock version 2.2 — the version almost everything targets today. wsa gets filled in with details about the loaded implementation the program never inspects. A non-zero return means initialization failed, and the only sane response is to print WSAGetLastError() and exit.

Creating a socket, then giving it an address

The socket itself

server.c
SOCKET server = socket(AF_INET, SOCK_STREAM, 0);

if (server == INVALID_SOCKET) {
    printf("Could not create socket : %d\n", WSAGetLastError());
    WSACleanup();
    return 1;
}
ArgumentMeans
AF_INETIPv4 addressing
SOCK_STREAMTCP — a reliable, ordered byte stream
0Let the OS pick the matching protocol for that type

Put together: an IPv4 TCP socket.

Describing an address

server.c
struct sockaddr_in addr;
memset(&addr, 0, sizeof(addr));

addr.sin_family = AF_INET;
addr.sin_addr.s_addr = INADDR_ANY;
addr.sin_port = htons(PORT);

memset() zeroes the struct first, so no leftover stack memory ends up in fields the code never explicitly sets. sin_family = AF_INET marks it as IPv4. INADDR_ANY means "accept connections on every local network interface at once" rather than one specific IP — for local testing, that's reachable at 127.0.0.1 or localhost. htons(PORT) — Host TO Network Short — reorders the port number's bytes into the order network protocols expect, since a Windows machine's native byte order doesn't have to match the network's.

Binding it

server.c
if (bind(server, (struct sockaddr*)&addr, sizeof(addr)) == SOCKET_ERROR) {
    printf("Bind failed with error code : %d\n", WSAGetLastError());
    closesocket(server);
    WSACleanup();
    return 1;
}

bind() expects a pointer to the generic struct sockaddr, and addr is the more specific struct sockaddr_in — the cast satisfies the compiler without changing a single byte in memory. If bind() fails, the usual culprits are a port that's already in use or a process without permission to claim it.

Listening, then accepting

server.c
if (listen(server, 10) == SOCKET_ERROR) {
    printf("Listen failed with error code : %d\n", WSAGetLastError());
    closesocket(server);
    WSACleanup();
    return 1;
}

The 10 isn't a client limit — it's the size of the queue for connections that have arrived but haven't been accepted yet. The socket is now in a listening state, waiting.

server.c
while (1) {
    SOCKET client = accept(server, NULL, NULL);
    /* handle this client, then loop back */
}

accept() blocks until a browser connects, then hands back a second socket dedicated to that one client — the original server socket keeps listening for whoever's next.

No threads

This server reads the request, serves the file, and closes the connection before it loops back to accept() again. One slow client makes everyone behind it wait — more on that trade-off later.

Reading what the browser asked for

server.c
char buffer[2048];
int bytesReceived = recv(client, buffer, sizeof(buffer) - 1, 0);
buffer[bytesReceived] = '\0';

recv() is told to accept at most 2047 bytes — one short of the buffer's real size. The last slot is reserved so the code can drop a '\0' on the end afterward and treat the request as an ordinary C string, which is what the next step needs.

server.c
char method[10], path[256];
sscanf(buffer, "%s %s", method, path);
anatomy of a request line
GET /index.html HTTP/1.1
 │      │            │
 │      │            └─ discarded
 │      └────────────── path
 └───────────────────── method

sscanf() pulls the first two space-separated tokens into method and path. The HTTP version gets parsed by the same format string, but since the code never looks at it again, it's simply discarded.

server.c
if (strcmp(path, "/") == 0) {
    strcpy(path, "/index.html");
}

A bare / becomes /index.html — the one line that gives the server a homepage.

Staying inside the folder

server.c
if (strstr(path, "..")) {
    send_404(client);
}

Without this, a request for /../secret.txt would get concatenated straight onto ./public and could resolve to a file outside the folder the server is supposed to be confined to. Checking for two consecutive dots is a blunt way to catch that.

Worth knowing

This is a substring check, not real path validation — it can misfire on legitimate filenames and it's not what a production server should rely on. More on that in where it stops.

Turning a URL into a file path

server.c
char full_path[512];

snprintf(full_path, sizeof(full_path), "%s%s", PUBLIC_DIR, path);

With PUBLIC_DIR set to ./public and path set to /index.html, the result is ./public/index.html. snprintf() is handed sizeof(full_path) explicitly, so it can't write past the 512 bytes actually allocated. sprintf() would trust the input completely; snprintf() doesn't have to.

Serving the file

Everything above exists to get here. serve_file() does six things, in order:

  4. 4

Opening it

server.c
FILE *file = fopen(file_path, "rb");

"rb" — read, binary. Binary mode matters because most of what lives in public/ isn't text.

If it isn't there

server.c
if (!file) {
    send_404(client);
    return;
}

fopen() returns NULL rather than raising an error when a file is missing or unreadable — that NULL is the only signal the server needs to send a 404 and stop.

Measuring it

server.c
fseek(file, 0, SEEK_END);
long file_size = ftell(file);
fseek(file, 0, SEEK_SET);

Jump to the end, ask where the file pointer landed — at the end, that position is the size in bytes — then jump back to the start before actually reading anything.

Naming it

server.c
const char *ext = strrchr(path, '.');

strrchr() finds the last dot in the path rather than the first, which matters for names like archive.tar.gz.

Writing the headers

server.c
const char *mime_type = get_mime_type(file_path);
char header[512];

int header_len = sprintf(header,
    "HTTP/1.1 200 OK\r\n"
    "Content-Type: %s\r\n"
    "Content-Length: %ld\r\n"
    "Connection: close\r\n"
    "\r\n",
    mime_type, file_size);

send(client, header, header_len, 0);

Content-Type comes straight out of the lookup table. Content-Length tells the browser exactly how many body bytes to expect, computed from the fseek/ftell trick above. Connection: close is a promise the server keeps a few lines later. HTTP headers end in \r\n — carriage return plus line feed, not just a line feed — and the blank line after the last header is what actually marks the boundary between headers and body.

Streaming the body

server.c
char buffer[8192];
size_t bytes_read;

while ((bytes_read = fread(buffer, 1, sizeof(buffer), file)) > 0) {
    send(client, buffer, (int)bytes_read, 0);
}

fclose(file);
Why 8 KB at a time

Nothing here ever holds a whole file in memory. A 2 KB stylesheet and a 200 MB video get read the exact same way, in the exact same size chunks, until fread() returns 0 at end of file.

Why bytes, not strings

fread() and send() move raw bytes. C string functions stop at the first '\0', and a binary file — a PNG, in particular — can have plenty of those in the middle. Treating the body as a string would truncate it. Treating it as bytes doesn't.

Sending a 404

HTTP response
HTTP/1.1 404 Not Found
Content-Type: text/html
Content-Length: 48

<html><body><h1>404 Not Found</h1></body></html>

Same shape as the 200 response — status line, headers, blank line, body — just a different status and a small hand-written HTML body instead of a file read off disk.

One request, start to finish

Say public/index.html contains one line: <h1>Hello World</h1>. Here's the exchange it produces:

request
GET / HTTP/1.1
Host: localhost:8080
response
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 20
Connection: close

<h1>Hello World</h1>
  1. recv() reads the request
  2. method becomes GET, path becomes /
  3. / is rewritten to /index.html
  4. ./public + /index.html → ./public/index.html
  5. fopen() opens it, in binary mode
  6. fseek/ftell find its size — 20 bytes
  7. the extension .html maps to text/html
  8. the 200 header goes out
  9. the 20 bytes of HTML go out, in one chunk
  10. closesocket(client) ends the connection

Closing things properly

After the last send(), closesocket(client) ends that one connection — matching the Connection: close header already sent, so the browser knows not to expect anything more without asking again. The server socket itself stays open and loops back to accept(); only when the whole program shuts down do closesocket(server) and WSACleanup() run.

Where it stops being production code

This is a genuinely useful way to learn what a web server is doing underneath the framework. It is not something to point at the internet. A few of the corners it cuts:

  • send() can return early. It's allowed to transmit fewer bytes than asked. The code assumes every call sends everything; a robust server loops until the byte count actually adds up.
  • recv() is only ever called once. TCP is a stream, not a sequence of neatly-arranged messages — a request can arrive in pieces, and production code keeps reading until it sees the \r\n\r\n that ends the headers.
  • The HTTP method is never checked. GET, POST, and DELETE are all treated identically right now.
  • sscanf() has no width limit. Unexpectedly long input can write past the end of the fixed-size method and path buffers; %9s / %255s closes that.
  • The traversal check is a substring match, not real path validation — it can miss real attacks and reject harmless filenames alike.
  • MIME matching is case-sensitive. IMAGE.PNG won't match .png in the table.
  • The header is built with sprintf(), not the bounded snprintf() used everywhere else.
  • There's no concurrency. One client at a time, and a slow one blocks the rest.

A more serious version of this server would hand each accepted connection to its own thread, or use I/O multiplexing, so a slow client stops holding up everyone behind it. It would also add path canonicalization, proper URL decoding, request- and header-size limits, and correct handling of partial reads and writes.

Complete server.c

Here is the complete source used for the project. It is intentionally small so the socket lifecycle and request-to-file path stay visible.

server.c — complete source
#define _WIN32_WINNT 0x0601
    #include <stdio.h>
    #include <stdlib.h>
    #include <string.h>
    #include <winsock2.h>
    #include <ws2tcpip.h>

    #pragma comment(lib, "Ws2_32.lib")

    #define PORT 8080
    #define PUBLIC_DIR "./public"

    const char* get_mime_type(const char *path) {
      const char *ext = strrchr(path, '.');
      if (!ext) return "application/octet-stream";
      if (strcmp(ext, ".html") == 0 || strcmp(ext, ".htm") == 0) return "text/html";
      if (strcmp(ext, ".css") == 0) return "text/css";
      if (strcmp(ext, ".js") == 0) return "application/javascript";
      if (strcmp(ext, ".png") == 0) return "image/png";
      if (strcmp(ext, ".jpg") == 0 || strcmp(ext, ".jpeg") == 0) return "image/jpeg";
      if (strcmp(ext, ".gif") == 0) return "image/gif";
      if (strcmp(ext, ".ico") == 0) return "image/x-icon";
      if (strcmp(ext, ".svg") == 0) return "image/svg+xml";
      if (strcmp(ext, ".json") == 0) return "application/json";
      return "text/plain";
    }

    void send_404(SOCKET client) {
      const char *response =
        "HTTP/1.1 404 Not Found\r\n"
        "Content-Type: text/html\r\n"
        "Content-Length: 48\r\n"
        "\r\n"
        "<html><body><h1>404 Not Found</h1></body></html>";
      send(client, response, (int)strlen(response), 0);
    }

    void serve_file(SOCKET client, const char *file_path) {
      FILE *file = fopen(file_path, "rb");
      if (!file) { send_404(client); return; }

      fseek(file, 0, SEEK_END);
      long file_size = ftell(file);
      fseek(file, 0, SEEK_SET);

      const char *mime_type = get_mime_type(file_path);
      char header[512];
      int header_len = sprintf(header,
        "HTTP/1.1 200 OK\r\n"
        "Content-Type: %s\r\n"
        "Content-Length: %ld\r\n"
        "Connection: close\r\n\r\n",
        mime_type, file_size);
      send(client, header, header_len, 0);

      char buffer[8192];
      size_t bytes_read;
      while ((bytes_read = fread(buffer, 1, sizeof(buffer), file)) > 0) {
        send(client, buffer, (int)bytes_read, 0);
      }
      fclose(file);
    }

    int main(void) {
      WSADATA wsa;
      if (WSAStartup(MAKEWORD(2, 2), &wsa) != 0) return 1;

      SOCKET server = socket(AF_INET, SOCK_STREAM, 0);
      if (server == INVALID_SOCKET) { WSACleanup(); return 1; }

      struct sockaddr_in addr;
      memset(&addr, 0, sizeof(addr));
      addr.sin_family = AF_INET;
      addr.sin_addr.s_addr = INADDR_ANY;
      addr.sin_port = htons(PORT);

      if (bind(server, (struct sockaddr*)&addr, sizeof(addr)) == SOCKET_ERROR) {
        closesocket(server); WSACleanup(); return 1;
      }
      if (listen(server, 10) == SOCKET_ERROR) {
        closesocket(server); WSACleanup(); return 1;
      }

      printf("Serving '%s' at http://localhost:%d\\n", PUBLIC_DIR, PORT);
      while (1) {
        SOCKET client = accept(server, NULL, NULL);
        if (client == INVALID_SOCKET) break;

        char buffer[2048];
        int bytesReceived = recv(client, buffer, sizeof(buffer) - 1, 0);
        if (bytesReceived > 0) {
          buffer[bytesReceived] = '\\0';
          char method[10], path[256];
          sscanf(buffer, "%s %s", method, path);
          if (strcmp(path, "/") == 0) strcpy(path, "/index.html");

          if (strstr(path, "..")) {
            send_404(client);
          } else {
            char full_path[512];
            snprintf(full_path, sizeof(full_path), "%s%s", PUBLIC_DIR, path);
            serve_file(client, full_path);
          }
        }
        closesocket(client);
      }
      closesocket(server);
      WSACleanup();
      return 0;
    }

What's underneath

The server code only ever speaks one language: HTTP. Everything under that — the reliable byte stream, the addressing, the raw socket calls — is TCP, IPv4, and WinSock quietly doing their part.

What building it by hand teaches you

Frameworks exist so nobody has to write this twice. But writing it once — by hand, in C, against the raw WinSock API — is what makes a single line like app.get('/') stop looking like magic. Every request that hits this server takes the same path: a socket accepts a connection, a few hundred bytes get parsed by hand, a file gets opened, measured, typed, and streamed back in chunks, and the connection closes.

nginx and Apache do all of this too. They just do it faster, safer, and for more than one client at a time.
